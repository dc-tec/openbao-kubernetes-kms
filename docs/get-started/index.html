Get started

Take one Kubernetes cluster from no provider to Secrets stored as OpenBao Transit ciphertext in etcd.

On this page
  • The path
  • What you need

bao-kms-provider runs on every control-plane node and lets kube-apiserver encrypt Secrets and other resources with an OpenBao Transit key before they reach etcd. These steps set it up for one cluster, in order.

!

Preview release

The current release line is a preview. Use it for labs, staging, and evaluation. Do not protect production control planes with it.

The path

StepPageOutcome
1What the provider doesYou know what the provider protects, what it does not, and whether your platform fits.
2Choose a deployment modelYou pick systemd or static pod for the control-plane nodes.
3Plan identity valuesYou have recorded every name and identity value the later steps reuse.
4Prepare OpenBaoOpenBao holds the Transit key, the policy, and the JWT role.
5Download the releaseYou have a verified artifact for your deployment model.
6Run with systemd or Run as a static podThe provider runs on every control-plane node and passes doctor.
7Enable encryptionThe API server encrypts through the provider, and existing Secrets are rewritten.
8Verify encryptionetcd holds only ciphertext, and the identity fallback is removed.

What you need

  • A Kubernetes 1.34 or 1.35 cluster whose control-plane nodes you can administer. See Reference: Compatibility for the tested matrix.
  • An OpenBao 2.6 cluster reachable over HTTPS from every control-plane node, and an administrator token for it.
  • A JWT issuer for the provider’s host credential that keeps working when the protected API server is down.
  • On your workstation: the bao CLI, cosign, and an authenticated GitHub CLI (gh).

To try the provider without a cluster or OpenBao of your own, contributors maintain a local lab that builds the provider from source and wires it into a Kind cluster with one command. See Contribute: Local lab .

After Get started, continue with Operate for rotation, upgrades, and recovery, and Configure for auth and policy variants and monitoring.
